Does user tone change coding performance?

Preliminary local-model pilot · 5 tasks × 2 repetitions × 3 tones = 30 generations. Model: qwen2.5-coder:1.5b.

Interpretation: This is a pipeline pilot, not evidence that one tone is generally better. Only 5 hand-authored tasks were sampled; confidence intervals are exploratory and may be unstable. The report includes every planned generation, including invalid code and execution failures.

What was controlled

Task text and system instructions were identical across conditions. Only the prefix changed. Every generation used a fresh two-message conversation, without tools. Trial order was shuffled with seed 42. Sampling temperature 0.7, top-p 0.95, output limit 1536 tokens. Generation seeds were paired across tones within each task/repetition. No retries or solution repairs.

  • neutral: Here is a coding problem for you to solve.
  • friendly: I'd appreciate your help solving this coding problem. Thanks!
  • adversarial: I doubt your ability to solve this coding problem.

Limits and next experiment

One small quantized model, fixed tone phrases, two repeats, and five custom tasks cannot establish a general tone effect. Difficulty labels are informal. Training overlap is unknown. Hidden tests measure correctness only on covered inputs, not a proof of correctness. Wording and token length still differ between prefixes. Seeds improve traceability but do not promise bit-for-bit reproducibility across hardware/runtime versions. Latency includes model warm-up and is not a treatment outcome.

Freeze this pilot; next use 30–50 independently selected tasks and 3–5 repeats, and repeat on another model. Keep task-level paired comparisons as the primary analysis; do not treat individual test cases as independent observations.
